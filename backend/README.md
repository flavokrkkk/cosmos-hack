# Backend

FastAPI обслуживает каталог, расчёт, подбор и сравнение портфелей Case 02.
Расчёт детерминированный; Ollama нужна только для текстовых пояснений и по умолчанию
отключена. PostgreSQL, Redis, worker, регистрация и внешние ключи текущему API не нужны.

Запуск всего приложения через Docker описан в [корневом README](../README.md).
[`scripts/run_local.py`](../scripts/run_local.py) поддерживает `--ollama off`, `on`
и `host`: без модели, с моделью в контейнере или с установленной Ollama.
Расчёт без веб-приложения — в [документации CLI](app/core/services/portfolio_engine/README.md).

## Локальный запуск API без Docker

Нужен Python 3.12. Из корня репозитория:

```bash
python3.12 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
cd backend
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Swagger: `http://localhost:8000/docs`; проверка запуска: `http://localhost:8000/health`.
Для своих настроек создайте `backend/.env` на основе [`.env.example`](.env.example).
Значения по умолчанию позволяют работать без этого файла и без Ollama.
Переменные окружения имеют приоритет над `.env`; после изменения настроек перезапустите API.

Конфигурация — `AppSettings` и `OllamaSettings` в
[`config.py`](app/infrastructure/config/config.py); префикс переменных — `COSMOS_`.
Для отдельного frontend задайте его origin через `COSMOS_CORS_ALLOWED_ORIGINS`;
по умолчанию разрешён `http://localhost:5173`.

## API

Маршруты публичные, токен не нужен. Административные auth-маршруты в текущем приложении
не подключены. Браузер использует прокси `/api/portfolio/*`; непосредственно FastAPI
обслуживает `/portfolio/*`. Схемы запросов и ответов доступны в Swagger и
[`core/dto/portfolio.py`](app/core/dto/portfolio.py).

- `GET /health` — `status="ok"` и `capabilities.ollama_enabled`. Флаг сообщает,
  включена ли генерация, и не подтверждает готовность модели.
- `GET /portfolio/catalog` — лоты, режимы, пороги, метод, критерии, ссылки на исходники
  и `dataset_hash`.
- `POST /portfolio/evaluate` — пересчёт заданного состава и режимов, BASE и STRESS.
- `POST /portfolio/recommend` — подбор четырёх лотов с режимами, альтернативы и анализ выбора.
- `POST /portfolio/compare` — сравнение двух–четырёх полных портфелей; разницы
  считаются относительно первого, включая все шесть критериев выбора.
  Остаток передаётся в `deltas[].annual_surplus_mrub` и берётся из
  `variants[].financial.annual_surplus_mrub`; три индекса — из `metrics`.
- `POST /portfolio/explain` — пояснение полного портфеля.
- `POST /portfolio/compare/analyze` — пояснение сравнения двух–четырёх разных полных портфелей.

Сначала получите `dataset_hash` из каталога. Он обязателен для расчёта и подбора;
при сравнении передаётся для каждого портфеля. Сервер сам пересчитывает состав
и не принимает готовые метрики от клиента.

### Проверка заданного состава

`evaluate` принимает `dataset_hash` и `selection` — список объектов
`{"lot_id":"FIRE","mode_id":"A"}`. Допустимы ноль–четыре уникальных лота;
режимы A/B/C берутся из каталога. Четыре лота дают `status="complete"`.
Пустой выбор возвращает `status="incomplete"`, `metrics=null`; один–три лота —
предварительный расчёт и невыполненное требование к размеру портфеля.

`evaluate` не принимает `scenario`: ответ содержит проверки обоих сценариев.
В `explain` и `compare/analyze` поле `scenario` допускает только `BASE` или `STRESS`,
по умолчанию `STRESS`. Официальный STRESS меняет бюджетный лимит C0,
а не стоимость лотов или формулы показателей.

Дубликаты, неизвестные лоты/режимы, пятый лот в `evaluate`, неизвестный сценарий
и лишние поля возвращают 422. Другая версия данных возвращает 409.
Нарушение ограничения кейса — ответ 200 с результатами проверок, а не ошибка HTTP.

### Подбор

У `recommend` единственный метод — `hybrid_maximin_v1`. Параметры:

- `require_stress`: `true` по умолчанию — проходят BASE и STRESS; `false` — достаточно BASE.
- `lot_ids`: от четырёх до восьми разных лотов-кандидатов; выбираются ровно четыре
  с режимами. Отсутствующее поле или `null` — поиск по всему каталогу.
  При четырёх кандидатах состав фиксирован; при большем числе альтернативы могут
  отличаться составом. Порядок ID нормализуется и не меняет результат.
- `cash_loss_limit_mrub`: явная допустимая потеря остатка относительно максимума S
  либо `null`. При `null` сначала максимизируется Q, затем S; автоматический Δ
  показывает денежную уступку ради этого выбора.
- `quality_epsilon`: только `0`.
- `budget_cap_mrub`, `vpub_floor_mrub_per_year`, `required_public_lot_ids`:
  дополнительные ограничения поверх обязательных условий кейса.
- `with_explanations`: `true` по умолчанию. С `false` возвращается расчёт без
  ожидания генерации; `explanation` у вариантов равен `null`.
  Флаг не меняет победителя и вычислительный `input_hash`.

Прежние методы, веса, менее четырёх кандидатов, дубликаты и неизвестные ID — 422.
Ответ повторяет нормализованный `request`, содержит победителя, альтернативы
и счётчики рассмотренных/допустимых вариантов и фронта Парето.
В `analysis` доступны шесть оценок, Q, шкалы, Δ, точки смены победителя и отдельные
проверки чувствительности. Шкалы строятся по официально допустимому множеству
до ограничения кандидатов и дополнительных условий запроса.
Обоснование — в [описании принятого метода](../docs/22-hybrid-selection.md).

Если решения нет: `status="no_feasible"`, `recommended=null`, `alternatives=[]`.
Backend не расширяет список кандидатов и не ослабляет условия автоматически.
Frontend сначала запрашивает расчёт с `with_explanations=false`, затем пояснения.
Черновик, сохранённые варианты и JSON-экспорт/импорт реализованы в браузере;
backend портфели не хранит.

## Ollama

При `COSMOS_OLLAMA_ENABLED=false` HTTP-клиент Ollama не создаётся. Все три пути
пояснений сразу возвращают детерминированный текст по расчётным фактам, без
ожидания модели или её очереди. В ответе: `generated_by="template"`, `model=null`
и нейтральное сообщение об отключении. Для пакетного пояснения и сравнения
также возвращается `composition="extractive"`. Расчётные функции работают полностью.

Для установленной на той же машине Ollama подготовьте модель:

```bash
ollama pull qwen3:4b-instruct
```

Запустите Ollama и задайте в `backend/.env`:

```dotenv
COSMOS_OLLAMA_ENABLED=true
COSMOS_OLLAMA_BASE_URL=http://localhost:11434
COSMOS_OLLAMA_MODEL=qwen3:4b-instruct
COSMOS_OLLAMA_TIMEOUT_SECONDS=45
```

Перезапустите API. Веса хранятся средствами Ollama, в контейнерном режиме —
в именованном Docker volume; они не включаются в Git.

Модель `qwen3:4b-instruct` выбрана для русскоязычного структурированного объяснения готовых
фактов. [Каталог Ollama](https://ollama.com/library/qwen3/tags) указывает размер около 2,5 ГБ;
[карточка Qwen3-4B](https://huggingface.co/Qwen/Qwen3-4B) — лицензию Apache-2.0.
[Qwen3](https://qwenlm.github.io/blog/qwen3/) поддерживает русский язык;
[JSON Schema Ollama](https://docs.ollama.com/capabilities/structured-outputs)
ограничивает структуру ответа. Это не гарантия достоверности: backend проверяет факты,
а модель не получает права менять состав или выполнять расчёт. Модель заменяется через
`COSMOS_OLLAMA_MODEL` без правки API.

При включении запрос может ждать ответа модели. Ошибка подключения, тайм-аут
или неприемлемый ответ приводят к пояснению по расчётным данным; числа и рекомендация
сохраняются. `generated_by`, `model` и `warning` различают генерацию и шаблон.
Кеш учитывает режим работы, модель и входные данные.

Для удалённой Ollama `COSMOS_OLLAMA_BASE_URL`, `COSMOS_OLLAMA_USERNAME` и
`COSMOS_OLLAMA_PASSWORD` задаются только на backend. При заданных имени пользователя
и пароле используется Basic Auth; frontend не получает адрес или учётные данные.
Серверное развёртывание описано в [корневом README](../README.md).

Модель не выбирает лоты/режимы и не вычисляет показатели. Числа и разрешённые факты
формирует расчётное ядро. Проверяются структура ответа и ссылки `fact_ids`, числовые
утверждения в свободном тексте модели не принимаются. Произвольного `prompt` в API нет.

## Реализация и входные файлы

Чистое ядро — [`app/core/services/portfolio_engine/`](app/core/services/portfolio_engine/).
Оно не импортирует FastAPI, БД или Ollama. CLI запускает этот же пакет напрямую,
без второй реализации формул и корневых переходников. Роутеры вызывают сервисы;
HTTP-интеграция модели находится в `OllamaClient`, сборка запросов — в `OllamaService`.

Исходники читаются из `case/source/`, в автономном комплекте — из `data/official/`.
Другой путь задаётся через `COSMOS_CASE_SOURCE_DIR` до запуска процесса.
Проверяются `case_core.py`, `data/lots.csv`, `data/access_modes.csv` и
`config/case_config.json`; их версия входит в `dataset_hash`.
После изменения набора нужны перезапуск и новый хеш из каталога.

Для интерактивного сценария запросы `evaluate`, `recommend`, `compare` и `explain`
принимают необязательный полный снимок `inputs`: восемь лотов и три режима A/B/C.
Он применяется только к данному расчёту, не меняет файлы организаторов и входит в
`input_hash`. Без `inputs` используются официальные значения.

[`config/decision.json`](../config/decision.json) задаёт условия и допущения
командного CLI-расчёта, а не готового победителя. API получает условия из запроса;
для сравнения CLI и API используйте одинаковые условия.
Канонические показатели сохраняют исходную точность. При ранжировании машинный
шум убирается до восьми знаков, затем сравниваются рациональные значения.

При старте пространство решений прогревается вне event loop. Вычисления идут
через thread pool и кешируются в памяти; очередь задач не нужна. Версии и хеши
возвращаются в API. Кеш отдаёт независимые копии результатов.

## Проверки

Из корня репозитория:

```bash
backend/.venv/bin/python -m pip install -r backend/requirements-dev.txt
backend/.venv/bin/python -m pytest tests backend/tests -q
backend/.venv/bin/python -m backend.app.core.services.portfolio_engine selfcheck
```

Проверка импорта и OpenAPI:

```bash
cd backend
PYTHONPYCACHEPREFIX=/tmp/cosmos-hack-pycache .venv/bin/python -m compileall -q app migrations
.venv/bin/python -c "from app.main import app; print(sorted(app.openapi()['paths']))"
```

Тесты покрывают совпадение с каноническим расчётом, воспроизводимость, валидацию
запросов, пояснения и отсутствие обращений к отключённой модели. Внешняя Ollama
в тестах подменяется: unit/API-тесты сами по себе не подтверждают работу Docker
или реальной модели. Зависимости зафиксированы в [requirements.txt](requirements.txt)
и [requirements-dev.txt](requirements-dev.txt).
