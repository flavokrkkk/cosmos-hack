# ТЧК MISIS — расчётный комплект, Кейс 02

Межрегиональный портфель космических сервисов. Единственный метод выбора — `hybrid_maximin_v1`: обязательные ограничения → максимум слабейшей из шести оценок Q → максимум годового денежного остатка S. При явно заданном Δ перед сравнением Q дополнительно ограничивается допустимая потеря S. Канонические формулы организаторов неизменны.

**Контрольная рекомендация:** FIRE:A, AGRI:C, TRANS:C, ENV:A. C0=1129,8 млн ₽; OPEX=305,75 и CASH=398,0 млн ₽/год; S=92,25 млн ₽/год; VPUB=1199,0 млн ₽/год; Q=0,5. BASE и STRESS: по девять PASS. Запас C0 в STRESS=50,2 млн ₽.

**Начните с [результата выбора](results/hybrid_analysis.json):** портфель, шесть оценок и проверки BASE/STRESS. В `results/` только четыре файла: этот отчёт, показатели портфеля, расчёт по лотам и конфигурация решения.

**Статус комплекта:** расчёт, данные, входы, результаты и тесты готовы для автономной проверки. Наличие финальной записки, одностраничного резюме и презентации отмечено в `manifest.json`, поле `missing_materials`. Этот перечень нельзя считать закрытым только потому, что расчёт запускается.

## Запуск с нуля

Проверенная среда: Python 3.12.14, pandas 2.3.3, numpy 2.5.3, pytest 8.4.2. Python 3.12; зависимости зафиксированы в `requirements.txt`. Веб-сервер, PostgreSQL, Redis и Ollama для этих команд не нужны. Нет регистрации, ключей API или платных сервисов. Интернет нужен только для установки зависимостей.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python run.py selfcheck
.venv/bin/python -m pytest tests -q
.venv/bin/python run.py recommend
.venv/bin/python run.py evaluate --scenario BASE
.venv/bin/python run.py evaluate --scenario STRESS
```

В Windows используйте `.venv\Scripts\python.exe` вместо `.venv/bin/python`. Команды запускайте из каталога комплекта. Сам комплект можно переместить отдельно от исходного веб-проекта.

## Файлы и изменение входов

[Расшифровки обозначений, столбцов CSV и единиц измерения](docs/algorithm.md#словарь-результатов).

- `src/engine/hybrid.py` — единственная логика выбора, ровно та же, что вызывается API основного приложения.
- `src/engine/canonical.py` — адаптер формул; `constraints.py` — диагностика границ.
- `data/official/` — неизменная копия входов организаторов, включая `case_core.py`, два CSV и `config/case_config.json`.
- `config/decision.json` — параметры алгоритма, альтернативы, управленческие допущения и источники. Рекомендованный состав вычисляется, а не берётся из этого файла как готовый ответ.
- `results/hybrid_analysis.json` — выбор и шесть оценок; `checks` — BASE/STRESS, `search_summary` — итоги перебора, `headroom` — запасы, компактные альтернативы и сценарии.
- `results/portfolio_metrics.json` — итоговые показатели; `portfolio_detail.csv` — расчёт по каждому лоту; `team_decision_config.json` — состав, параметры, допущения и происхождение экспорта.
- `tests/` — формулы, ограничения на границах, воспроизводимость, точные границы Δ и отсутствие доминируемого победителя.
- `docs/management-note.md` — управленческая записка по продуктовым критериям П1–П9 с приложениями: реестр рисков, матрица ответственности и KPI, пролотовый расчёт, источники. `docs/stress-summary.md` — обязательное резюме стресс-сценария.
- `docs/algorithm.md` — предметное обоснование, связи лотов и режимов, источники и ограничения. `docs/README.md` — состояние материалов защиты.
- `manifest.json` — контрольные суммы и происхождение файлов. Notebook не входит в решение, поэтому папки `notebooks` нет.

В `algorithm_parameters` изменяйте `cash_loss_limit_mrub`, `require_stress`, `budget_cap_mrub`, `vpub_floor_mrub_per_year`, `required_public_lot_ids`, `lot_ids`. Нулевой Δ допустим; отрицательные и нечисловые значения отклоняются. `quality_epsilon` фиксирован на 0. Условные шкалы и Δ — допущения команды, не требования организаторов.

Пустой (`null`) Δ вычисляется как минимальная потеря S для достижения глобально максимального Q: на контрольных данных 9,5 млн ₽/год. Это приоритет Q, математически эквивалентный Q → S, а не независимый денежный предел. Числовой Δ даёт отдельное ограничение допустимой потери. Min–max шкалы фиксированы по всей официально допустимой области выбранного сценария до дополнительных фильтров. Поэтому изменение Δ или состава кандидатов не перенормирует оценки.

```bash
.venv/bin/python run.py recommend --delta 5
.venv/bin/python run.py recommend --base-only
.venv/bin/python run.py evaluate --portfolio FIRE:A,AGRI:B,TRANS:B,ENV:A --scenario STRESS
.venv/bin/python run.py compare
.venv/bin/python run.py sensitivity --scenario STRESS
.venv/bin/python run.py export
```

`--base-only` запускает новый поиск в BASE. Для проверки того же выбранного состава при другом официальном бюджете используйте `evaluate --scenario`, как в первом блоке. Глобальный `--config path.json` ставится перед командой. `export` перезаписывает результаты текущими расчётами; исходный контрольный снимок остаётся в Git. Для изменённой копии официальных входов задайте `COSMOS_CASE_SOURCE_DIR` и перезапустите процесс; контрольные числа относятся к исходной версии, не к произвольным новым данным.

## Короткая проверка для технического эксперта

Скачанный из веб-интерфейса `team_decision_config.json` воспроизводится командой
`run.py evaluate --snapshot /путь/team_decision_config.json`: берутся сохранённые состав,
цены и коэффициенты, новый подбор не запускается. Для изменения исходных параметров
в конфигурации служит `algorithm_parameters.inputs` (полные восемь лотов и три режима A/B/C;
снимок `inputs` есть в выгрузке UI). Все команды CLI используют эти входы. Для эксперимента
используйте `export --output /путь/результаты`, чтобы сохранить контрольные четыре файла.
При нулевом суммарном OPEX KCASH не определён: инструмент сообщает об ошибке.
Управленческие поля из UI с пометкой `reference_requires_review` — обоснование исходного
решения команды, применимость которого к эксперименту нужно пересмотреть.

**ФАКТ:** эти действия проверяют сценарии §14 [инструкции кейса](data/official/README.md#14-проверка-перед-защитой). Расчёт выполняется локально, без Ollama и без обращения к нейросети; готовые файлы `results/` не подставляются вместо вычислений.

1. `run.py selfcheck` проверяет воспроизводимость расчёта и рекомендации. `run.py evaluate` показывает исходный состав, SHA-256 входов, показатели и диагностику каждого ограничения в обоих сценариях.
2. Измените режимы через `run.py evaluate --portfolio FIRE:A,AGRI:B,TRANS:B,ENV:A`. Сравнение с рекомендацией и остальными альтернативами доступно через `run.py compare`: в отдельных таблицах с общим номером варианта видны состав, денежные потоки, все шесть критериев и статусы BASE/STRESS. Собственные альтернативы добавляются в массив `alternatives` копии `config/decision.json`, без правки Python.
3. Проверьте нарушение на примере из справочного материала организаторов:

   ```bash
   .venv/bin/python run.py evaluate --portfolio FIRE:A,FLOOD:A,AGRI:C,TRANS:C
   ```

   Ожидается BASE PASS и STRESS FAIL по стартовым затратам. Таблица показывает официальный порог, фактический C0 и отрицательный запас. Для `evaluate` код завершения `1` означает обнаруженное нарушение, `2` — ошибку входов, `0` — успешную проверку. В `recommend` код `2` также означает отсутствие допустимого варианта при заданных условиях.
4. Границы всех девяти ограничений проверяются отдельно, на пороге и сразу за ним:

   ```bash
   .venv/bin/python -m pytest tests/test_engine.py -q -k every_official_boundary
   ```

   Это синтетические контрольные примеры для тестирования проверок, а не изменение данных кейса. Тест субсидируемого портфеля отдельно подтверждает, что отрицательный S не запрещён скрытым условием.

Настройки поиска меняйте в копии конфигурации и передавайте `--config` перед командой. Исходные CSV и официальные лимиты остаются неизменными. Экспертные обоснования — условия договоров, общественного доступа и допускаемые кейсом исключения — раскрыты в записке; числовой PASS не подтверждает их автоматически.
