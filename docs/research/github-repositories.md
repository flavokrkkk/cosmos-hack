## Решения предыдущего этапа серии в Ростове

Эти репозитории созданы 04–06.09.2026 и относятся к ростовскому этапу, поэтому
не решают нашу постановку «4 из 8 лотов». Они полезны как примеры того, что
другие команды положили в публичный конкурсный репозиторий.

### [Mojarung/kosmohack_rostov](https://github.com/Mojarung/kosmohack_rostov)

- **НАХОДКА:** полноценное решение мониторинга вегетационной динамики: React,
  FastAPI, модели восстановления пропусков NDVI, детекция аномалий, Docker,
  воспроизводимый инференс, тесты, исследовательские отчёты и презентация.
- **НАХОДКА:** особенно полезен как образец «быстрого старта для проверяющего»:
  одна команда `docker compose up --build`, явный маршрут демо, отдельные
  команды проверки метрики и подробная карта документации.
- **ФАКТ:** репозиторий опубликован под MIT License; есть
  [один публичный форк](https://github.com/verikirill/kosmohack_rostov).

### [DanielE330/kosmohack-2026](https://github.com/DanielE330/kosmohack-2026)

- **НАХОДКА:** решение команды FSociety для того же ростовского кейса по NDVI:
  Flutter-клиент, FastAPI/PostgreSQL, ML-контур, Docker/Caddy, инструкции запуска,
  база знаний и рабочее демо, указанное в README.
- **НАХОДКА:** репозиторий также подключён как submodule в портфолио автора
  [DanielE330/hackathons](https://github.com/DanielE330/hackathons). Это зеркало-
  указатель, а не отдельное решение.
- **НАХОДКА:** явного файла лицензии и распознанной GitHub лицензии при проверке
  нет; заимствовать код без отдельного разрешения нельзя.

### [3xfap2/shared-project](https://github.com/3xfap2/shared-project)

- **НАХОДКА:** «КОСМОБЕРЕГ» — решение другого ростовского кейса о популяризации
  проекта «Чистый берег». В репозитории есть интерактивный прототип, FastAPI,
  OpenAPI-контракт, Docker, презентация, сценарий защиты, реестр допущений,
  KPI, план, риски и архитектура.
- **НАХОДКА:** для нашей сдачи полезна структура доказательств: отдельное
  сопоставление каждого критерия с документом или экраном, воспроизводимая
  сквозная проверка прототипа и явная граница между демонстрационными и
  настоящими данными.
- **НАХОДКА:** явного файла лицензии и распознанной GitHub лицензии при проверке
  нет; заимствовать код без отдельного разрешения нельзя.

## Что применить в нашем репозитории

1. **[В]** Сохранить короткий маршрут проверки «одна команда → один URL → три
   действия демо → команды self-check». У ростовских решений это вынесено в
   начало README, что снижает риск потери технических баллов.
2. **[В]** Дать проверяющему карту «критерий → экран/документ/проверка». Особенно
   сильный пример — README «КОСМОБЕРЕГА».
3. **[В]** Не переносить из ростовских решений ML-архитектуру: их кейс имел
   датасет и автоматическую метрику, а наш движок — детерминированная арифметика
   по официальным параметрам.
4. **[В]** Не копировать код или визуальные материалы из репозиториев без ясной
   лицензии. Даже лицензированный MIT-репозиторий следует использовать только с
   сохранением требуемого уведомления и отражением источника в документации.

Проверены поиск репозиториев и коммитов GitHub по русским и английским маркерам:
названию серии, Нижнему Новгороду, обоим названиям кейсов, КЭП/АКИД, названию
постановки, кодам лотов и именам файлов официального комплекта. Дополнительно
проверены внешние поисковые выдачи `site:github.com`, публичные форки найденных
репозиториев, README, деревья файлов и история коммитов.

**Ограничение:** поиск выполнялся до стоп-кода текущего этапа. Повторная проверка
после 13.09.2026 может найти репозитории, которые команды откроют после сдачи или
которые успеют проиндексироваться.
