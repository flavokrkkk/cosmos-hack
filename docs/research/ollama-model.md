# Модель Ollama для объяснения портфеля

_11.09.2026 · [← индекс ресерча](README.md)_

## Решение

**ГИПОТЕЗА команды:** для локальной русскоязычной суммаризации расчёта использовать
`qwen3:4b-instruct` по умолчанию. Проверка — валидный структурированный ответ на контрольных
портфелях, приемлемая задержка на демонстрационном Mac и отсутствие выдуманных фактов.
Модель настраивается через `COSMOS_OLLAMA_MODEL`, поэтому решение можно заменить без правки API.

## Почему этот вариант

- **НАХОДКА:** официальный каталог Ollama указывает для `qwen3:4b-instruct` размер около
  2,5 ГБ и контекст 256K: <https://ollama.com/library/qwen3/tags>.
- **НАХОДКА:** официальный анонс Qwen3 заявляет поддержку 119 языков и диалектов, включая
  русский: <https://qwenlm.github.io/blog/qwen3/>.
- **НАХОДКА:** официальная карточка Qwen3-4B описывает многоязычность и лицензию Apache-2.0:
  <https://huggingface.co/Qwen/Qwen3-4B>.
- **НАХОДКА:** `qwen3.5:4b` в Ollama занимает около 3,4 ГБ и включает мультимодальные
  возможности: <https://ollama.com/library/qwen3.5%3A4b>. Для текущего текстового сценария
  эти возможности не используются, поэтому более тяжёлая модель не выбрана по умолчанию.
- **НАХОДКА:** Ollama умеет ограничивать ответ JSON Schema; документация рекомендует
  структурированный формат и низкую температуру: <https://docs.ollama.com/capabilities/structured-outputs>.

## Граница применения

Модель получает только короткие качественные факты, вычисленные backend, и возвращает JSON
с `fact_ids`. Она не получает право менять портфель, считать значения или принимать свободный
prompt пользователя. Числа остаются в объекте расчёта и отображаются интерфейсом отдельно.
Невалидный ответ заменяется детерминированным шаблоном, поэтому Ollama не является условием
работы калькулятора.
