# Frontend под дизайн-систему макетов — 12.09.2026

_Заметка по реализации · [Заметки](README.md) · решение — [05-decisions.md](../05-decisions.md#12092026--frontend-собран-заново-под-дизайн-систему-макетов)_

Кто: Egor + агент. Что: фронтенд собран заново по семи макетам дизайнера (автоподбор с
результатом, продолжение с объяснением и альтернативами, ручная проверка 0/4 → 1/4 → 4/4,
модалка лота). Код — `frontend/`, устройство — [frontend README](../../frontend/README.md).

## Что сделано (ФАКТ, проверено в браузере на живом бэкенде)

- **Автоподбор:** профиль и правило (из `catalog.methods`, раскрывается «Как выбираем»),
  тумблер «Искать только проходящие STRESS», кнопка «Подобрать портфель» и восемь лотов до
  запуска; после — «Портфель команды» веером из четырёх карточек с режимами, счётчики перебора,
  «Подобрать заново», блоки «Текущий портфель» (исходное × коэффициент = после режима),
  «Проверка этого портфеля» (BASE/STRESS меняет только пороги), «Проверка ограничений»
  (девять плиток, нарушение — красным и словом), действия «Сохранить вариант / Сравнить /
  Изменить вручную», выгрузка CSV/JSON, «Почему такой выбор?», «Альтернативы и сравнение».
  Состояния: до запуска, загрузка, ошибка с «Повторить», `no_feasible` с «Искать в BASE»,
  «условие изменено» после переключения тумблера.
- **Ручная проверка:** каталог в две колонки с «Выбрать / Выбрано», счётчик N из 4,
  приглушение остальных при 4/4, справа чипы состава, режимы после ответа сервера,
  показатели и проверки, «другие режимы для выбранных лотов», отсутствие сочетания режимов —
  отдельное состояние.
- **Модалка лота:** финансовые показатели, индексы и признаки, территория и возможности,
  подсказки из плана §13.2; при открытом расчёте — значение после режима и «исходно × k».
- **Сравнение:** диалог 2–4 вариантов (портфель команды, опорные точки, ручной, сохранённые),
  дельты к базе с подписью «выигрыш / плата», BASE и STRESS для одного состава.
- **Сохранение:** диалог имени и комментария (RHF + yup), список сохранённых, открытие с
  пересчётом, предупреждение о другой версии данных.

## Что заметил в макетах и как решил

- На макете «1 из 4» показатели и проверки заполнены теми же числами, что и «4 из 4»
  (1186 / 298 / 769 / 1,66) — это заглушка. По плану §14 режимы назначает сервер после
  четвёртого лота, поэтому денег при 1–3 лотах нет. Вместо них при 1–3 лотах показан
  **прогресс сборки** по условиям, не зависящим от режима: лотов N / 4, территориальных
  архетипов n / ≥ 3, групп возможностей n / ≥ 2 и набор групп — подписью «набрано / пока
  не набрано», не «нарушено» (§13.5). Счётчики приходят из `evaluate` с техническим
  режимом-заглушкой (режим общественного ядра), который на них не влияет и пользователю
  не показывается. Затраты, поступления и общественное ядро — только после назначения режимов.
- Подпись «OPRX» на макете — опечатка, в интерфейсе «OPEX» (план §13.2).
- Заголовок «Рекомендуемые лоты» заменён на «Портфель команды»: после правки бэкенда 12.09
  алгоритм победителя не коронует ([заметка](2026-09-12-tool-note-alignment.md)).
- Дашборд не показывает «Рекомендация» как источник варианта нигде: только «выбран командой»,
  «опорная точка фронта», «ручная проверка», «сохранённый вариант».
- Переключатель BASE/STRESS по правилу кейса меняет только пороги, поэтому шесть показателей
  портфеля при переключении не меняются — это выглядело как «ничего не произошло» (замечание
  Egor 12.09). Добавлена строка под показателями: лимит стартовых затрат сценария, факт,
  запас или превышение и вердикт (бриф T1); плитка ограничения с порогом, зависящим от
  сценария, подписана «порог сценария BASE/STRESS». Числа — из `checks[scenario]`.

## Проверка объяснения через Ollama в Docker (ФАКТ, 12.09 ~01:30)

- Подняты сервисы compose `ollama` + `ollama-pull` (`COSMOS_OLLAMA_HOST_PORT=11435`, потому что
  `11434` на Mac занят Ollama.app, где стоит только `bge-m3`); модель `qwen3:4b` из `.env`
  скачана в том `cosmos-hack_ollama-data` (2,5 ГБ, ~11 МБ/с, ≈4 минуты). `app` ходит на
  `http://ollama:11434` внутри сети compose — порт хоста ему не нужен.
- `POST /portfolio/explain` для портфеля команды: **холодный вызов 1 мин 46 с, тёплый ≈ 49 с**
  (CPU-инференс в Docker на Mac, GPU контейнеру недоступен). Ответ `generated_by: ollama`,
  `model: qwen3:4b`, без предупреждений; в интерфейсе — «Суммаризировано AI · qwen3:4b»
  для BASE и STRESS. Таймауты: бэкенд 180 с (`.env`), фронт 240 с — запас есть, но на защите
  объяснение лучше запросить заранее или держать модель прогретой.
- До запуска контейнера бэкенд честно отдавал шаблон с `warning`; интерфейс показывал
  «Шаблонный текст · модель недоступна» и кнопку «Запросить у модели снова».

## Правки по замечаниям Egor и после слияния с бэкендом 12.09 (~02:30)

**ФАКТ — что изменилось на бэкенде (коммиты сокомандника `1378e69`, `b87fb81`):** объяснения
теперь приходят внутри `POST /portfolio/recommend` (`variant.explanation`, одна пакетная
генерация на все варианты, серверный кеш 24 ч), `lot_ids` принимает 4–8 лотов-кандидатов,
добавлен `POST /portfolio/compare/analyze`. Замер на этой машине (Ollama в Docker, CPU):
**первый `recommend` — 74,7 с и всё равно шаблон** (пакет из пяти вариантов не укладывается
в таймаут), повторный — 0,01 с из кеша; через 15 с после шаблона кеш истекает и следующий
запрос снова ждёт. Для интерфейса это означало: клик «Подобрать портфель» и любое переключение
условия — минута ожидания без чисел.

**Решение — подбор в два шага (реализовано):** в `RecommendRequest` добавлен флаг
`with_explanations` (по умолчанию `true`, тесты бэкенда не меняются, `input_hash` от флага не
зависит); фронтенд сначала запрашивает расчёт без объяснений (0,003 с при прогретом кеше),
показывает числа, и вторым запросом с объяснениями заполняет блок «Почему такой выбор?». Шаблон
при недоступной модели помечается и не персистится в браузере; кнопка «Запросить у модели снова»
перезапрашивает только объяснение. Правило брифа AI1 «ошибка Ollama не блокирует подбор»
соблюдено. **Для защиты:** на процессоре пакет из 5 вариантов в 95 с не укладывается — нужна
нативная Ollama с GPU (или уменьшить `num_predict`/число вариантов в пакете), иначе везде шаблон.

**Верстка и тексты (замечания Egor):**
- соседние карточки больше не растягиваются при раскрытии «Подробнее о портфеле» — колонки
  выровнены по верху (`items-start`/`content-start`), высота каждой панели — своя;
- убран блок «Как выбираем»; описания сокращены до одной строки; из карточек альтернатив убраны
  показатели и встроенное объяснение — остались название, первое предложение причины, состав,
  BASE/STRESS и действие; строка сценария (лимит · факт · запас · вердикт) — одна строка;
- контейнер страницы 1440 px с полями 60 px и шрифты плиток (значение 16 px / подпись 12,5 px)
  сверены с макетом Figma (фрейм «Текущий портфель» 648 × 562, AUTO 1400, HAND 1440);
  просмотр Figma доступен без входа только в режиме чтения — размеры считаны по сетке 100 %.

**По отчёту валидатора ([notes/2026-09-12-frontend-case-validation.md](2026-09-12-frontend-case-validation.md)) сделано сразу:**
Т3 — при `no_feasible` в ручном режиме показана диагностика «Что нарушается» (тот же состав,
все лоты в режиме A, девять плиток с нарушениями и строка лимита); `t_rep` в сравнении подписан
нейтрально «Средний t_rep»; экспорт переименован в `calculation_snapshot.json` (не путать с
`config/decision.json`); в строке STRESS у портфеля команды добавлен ответ на стресс
«решение команды: портфель сохраняется без пересмотра» (бриф T2); подсказки открываются по
нажатию (touch); `request.with_explanations` в ответе бэкенда теперь повторяет реальный флаг;
ожидаемый `dataset_hash` записан в корневой README. Не сделано (решения команды): ручной выбор
режима A/B/C (Т2, README кейса §14 сц. 2), обновление манифеста материалов (GitVerse, PDF,
презентация), `/admin/auth` в backend README, судьба AI-блока на защите.
